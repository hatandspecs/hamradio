Seven Features, and What the Panel Found

Published on: October 23, 2026  · 

I added seven things to the ham radio cyberdeck in a day: a configurable function ring, a band plan reference, an antenna tuner that sweeps a band, a hotkey that logs the station you are working, a map for the WSPR spots, another for the contact log, and a way to get the files onto a phone. All of them had tests. The suite went from 3,146 checks to 3,994 and stayed green.

Then I put it on the deck, and found eleven faults in four sessions at the panel.

The features first, in the order an operating session actually uses them. The faults after.

Setting up

The function ring

^O and ^P walk between the deck’s applications — deck & rig, digimodes, logging, WSPR, band plan. Which ones are on that walk, and in what order, is now a screen rather than a constant in the source. Deck & rig cannot be removed, because it holds the system menu, but it can be moved.

The reason to make it configurable is that a field session and a shack session want different rings. Operating WSPR for a weekend, the band plan and the logger are in the way. Working a contest, WSPR is.

I specified two screens for this, copying the log schema editor: pick from a list, then order what you picked. I built one. Nineteen fields need two steps; five areas fit on one panel with room to spare. The key bindings are the schema editor’s, since those are already learned.

The band plan

A stop on the ring that lists the band segments for a license class, with their mode privileges. It is a reference, and a reference is worth having one key away while operating rather than on a phone in a pocket.

It carries US General and US Extra, with each band split into its CW/data and phone segments. I took the numbers from the regulation and followed what it said.

The auto tuner

The FTX-1 drives an external mAT-30 tuner, which stores a match per frequency. The tuner walks a set of band segments, stopping at each point to key the radio and trigger a match, so the radio ends up with a memory on every 10 kHz step of the bands I use. After that, changing frequency during a session recalls a stored match instead of running a fresh tune cycle.

The points sit 1 kHz inside each band edge and on 10 kHz multiples between. The segment list is the band plan’s, so the tuner never parks on a frequency the license class does not cover.

Each point gets a dwell, because the radio cannot report that an external tuner has finished — the RI status bit never clears. + and - set the dwell in half-second steps, the same keys that set squelch on the digimode tune screen. The dwell starts when the radio reports itself on the new frequency, not when the command was sent.

Operating

WSPR sessions

A WSPR session has a name and a start time, and every spot the deck decodes is filed under the session that was running. Sessions resume, start, rename and forget, from the F1 menu or F2, using the same keys as the contact log’s activities — a WSPR session and a log activity are the same idea, so they are the same workflow.

They are listed by name and start time to the minute in UTC. The time matters as much as the name: three sessions called general are indistinguishable by date alone, and for propagation the hour is the useful resolution anyway.

The point of naming a run is that it makes the log answerable afterward. “The 20 m spots from the Saturday night run” is a query only if the run had a name.

The WSPR map

One key from the WSPR screen draws the spots of the current session on a world coastline.

Every spot is a + and this station is an ×. One key changes the view between the focus projection and the globe, Esc leaves. That is the whole interface.

It is scoped to the session, which is what makes it worth a key: the question in the field is what this antenna, in this spot, is hearing tonight. Not what the deck has decoded since June.

The maps write pixels to /dev/fb0 directly rather than handing the framebuffer to fim or fbi, because handing over the framebuffer means handing over the keyboard too, and the deck is a keyboard-driven machine.

^G — log the station you are working

On the digimode conversation screen, ^G reads the callsign off the last received line and opens the log form with it filled in, along with the frequency, mode and time from the radio. Pressed again it steps back through earlier candidates.

The last received line is the right one. I specified the last transmitted line, which proves somebody was called, not that anybody answered. On receive the line reads KD3CCO DE K2ABC, so the other station is the token after DE. It also checks that the call before DE is mine, or two other stations working each other on the same frequency end up in my log.

The contact map

The same map, over the contact log, scoped to the current activity.

Contacts without a grid square are counted in the header rather than dropped, so a map showing eleven of forty contacts says so instead of looking like a quiet afternoon.

Afterward

Getting the files off

One key stands up a web page on the deck’s WiFi address and shows the URL. Type it into a phone and the log, the ADIF export, the WSPR spots, the transcript and the config file are downloadable.

No account, no app, no credentials, and it works on a field hotspot with no uplink — which is the case that rules out anything cloud-shaped. The address carries four random characters and the server closes itself five minutes after the last download. The request names a position in a list the deck handed the server, never a filename, so there is no path in it to traverse, and cyberdeck.secrets is not on the list.

What the panel found

That is how it works now. Most of those descriptions are the second version.

The auto tuner crashed the deck. One line passed self.rig, which does not exist — everywhere else uses self._log_rig(). Pressing Enter raised AttributeError, systemd restarted the terminal, and on the panel it looked like a pause and the screen escaping with the radio untouched.

The tests drive the sweep engine against a fake rig, and the screen tests drive the renderer. Nothing called the method that connects them. Both halves were tested and the wire between them was not. If a key starts something, a test should press the key.

The tuner swept against nothing. The CAT helper ignored its own return value, so a refused frequency command read as a successful one and the sweep walked through its whole segment list while the radio sat where it was. It checks the answer now and stops on a refusal.

The dwell was timed from the wrong moment. The tuner waited a fixed 0.3 seconds after commanding the VFO, then triggered the match. That is a guess about how long a radio takes to get there. Too short and the tuner matches the previous frequency; too long and every step in a long sweep pays for the worst case. It reads the dial back now and starts the dwell on arrival. A radio whose frequency cannot be read falls back to the fixed settle.

The band plan data was wrong. I had it carrying Technician and four reference plans for other countries that I did not need, and the Extra plan listed each band as a single range marked “All Modes”, which is not how the band is divided. Stripped to General and Extra, split into CW/data and phone segments.

The map drew and then disappeared. The framebuffer and the text console are the same memory. The draw loop opens with scr.erase(), so the picture — written once on entry — was overwritten a frame later. What survived were the cells curses thought were unchanged, which looked like a map squeezed into the top of the screen with fragments left behind on exit.

The blit runs after the refresh now, every frame, and covers only the rows between the header and the footer. Leaving a map blanks the framebuffer first, because the console is 66 columns of a 12-pixel font — 792 of the panel’s 800 — so the last eight pixels belong to no cell and clearok cannot reach them. A stripe of old map survived there on every exit.

No test could have caught this. The suite has no framebuffer.

The map was showing the wrong spots. It plotted every spot the deck had ever decoded — six thousand of them, from every night since I built it. Scoping it to the session fixed that, and then two things I had built for it were no longer worth their keys.

The band toggles went: within one session every band answers the same question, and which band a spot arrived on is a column in the spot list. The heard / heard-by filter went too, because the deck does not have that data. Its log holds what it decoded and what it transmitted; who heard the deck is on wsprnet, which needs a network a field deck often does not have. One of that filter’s two positions was always empty. I had taken the idea from my WSPR analysis work, which uses downloaded wsprnet data where both directions exist.

And then it was still showing the wrong spots. Scoping the map to the session was not enough, because the canvas cache keyed on the file’s size and modification time and not on which session was current. Start a fresh session, open the map, and the previous session’s several thousand spots came back out of the cache. The session name and start time are part of the cache key now.

The transmit interlock refused everywhere. ^B would not arm transmit unless the radio was in a data mode. That is right for digimodes and WSPR and wrong for the tuner, which keys the radio to match an antenna and does not care about the mode. The refusal was also written to the transcript, which the tuner screen does not draw, so the key looked dead rather than refusing. It applies to the two applications it belongs to now, and refusals report on the screen that raised them.

The transcript was full of housekeeping. Joining WiFi, pairing a keyboard, cycling the band plan’s license class, saving a ring order, the tuner starting and stopping — all of it went into the keyboard-to-keyboard transcript, which is meant to be a record of what went over the air. Each one goes to its own screen now.

An aborted over leaked into the next one. Ctrl-C drops the carrier through fldigi’s main.abort, but the text that had not gone out yet stays in fldigi’s transmit widget, and the deck adds each new over with text.add_tx, which appends. Abort halfway through a message, type something different, press Ctrl-T, and the remainder of the abandoned message goes out ahead of the new one. clear_tx existed in the client and had never been called. Abort stops the transmitter and then discards the text.

The callbook’s grid was being thrown away. The deck looks up name, QTH and grid for every callsign logged. The grid arrived and vanished, because the answer was written into the form and the general schema has no grid field. Every contact logged under that schema reached the file without a grid, which is why the contact map had nothing to plot. The log format has always carried grid and exports it as GRIDSQUARE; only the route from the lookup to the record was missing.

For contacts already in the log, the danger zone gained a line that looks up every callsign missing a grid, name or QTH and fills the gaps. One query per callsign, not per contact. It fills blanks and does not overwrite anything already typed.

The session picker was not where anyone would look for it. A WSPR session could be named and never returned to. The deck would come up on general, report six thousand heard in its header, and show an empty spot list, because the list only held what the current run had decoded. I put a session picker on F2 and considered it done. The F1 menu’s Session line still went to the name editor, which only starts a session. I looked in the menu for it myself and it was not there.

What I take from it

The eleven faults fall into three groups.

Some were things no test could reach: the framebuffer against curses, the transmit buffer surviving an abort, the VFO settle being a guess. The suite has no panel, no radio and no fldigi transmit widget to inspect.

Some were gaps between tested parts. The tuner crash is the clearest: both halves tested, the connection between them not. The cache key is the same shape of mistake — the scoping was tested, the cache was tested, and the fact that one invalidated the other was nobody’s test.

The rest were decisions I got wrong in the specification, which only showed up when I used the thing. A map of everything instead of a map of tonight. A filter for data the deck does not have. A session list reachable from a key but not from the menu. The code did what I asked it to.

Most of the improvement came from removing things.
